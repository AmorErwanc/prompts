## 项目概述

这是一个专门用于优化"海龟汤"（情境推理游戏）和规则怪谈AI裁判系统的项目。项目的核心目标是通过结构化的内容预处理来提高AI裁判的判断准确性，解决现有AI裁判系统在处理复杂推理内容时出现的判断错误、信息遗漏和幻觉问题。

### 项目核心架构
- **数据层**：原始的海龟汤和规则怪谈数据（CSV格式）
- **提示词系统**：三个专门的AI提示词模板
  - 内容解析专家：负责结构化原始故事内容
  - 裁判专家：基于结构化数据进行游戏裁判
  - 综合提示专家：统一处理不同类型内容
  - 提示专家：旨在提升海龟汤的提示内容
- **测试验证层**：包含多个版本的模型回答测试数据

## 核心工作流程

### 1. 内容预处理流程
```
原始汤面/汤底 → 内容解析专家 → 结构化知识库 → 裁判专家 → 游戏判断
```

### 2. 关键处理步骤
- **疑问确认**：AI主动识别原文中的模糊点并询问澄清
- **边界识别**：识别可能导致"是也不是"回答的边界情况
- **结构化解析**：将复杂故事转化为结构化的知识点
- **裁判决策**：基于结构化数据进行准确的游戏裁判

## 提示词编写规范

所有提示词必须遵循以下格式规范：
- 使用英文的 [] 标记模块或部分，如 [Role]、[Task]、[Skills]
- 不使用 ** 进行强调或标记
- 保持格式简洁清晰，避免过度标记
- 必须包含详细的工作流程和判断原则

## 数据结构说明

### CSV数据文件类型
- **长本格**：完整的海龟汤故事，包含复杂情节
- **短本格**：简化版的海龟汤故事
- **变格本**：带有特殊规则的变体故事
- **规则怪谈**：基于规则的恐怖推理故事

### 标准数据字段
- **汤面**：呈现给玩家的表面故事
- **汤底**：完整的真相和背景故事
- **问**：玩家提出的问题
- **答**：标准答案（是/否/是也不是/与此无关等）

## 测试和验证流程

### 模型测试数据
- **未转写版本**：直接使用原始汤面汤底的测试结果
- **转写版本**：使用结构化处理后的测试结果
- **不同模型版本**：1.5pro、1.6-seed、1.6-thinking等

### 验证方法
1. 对比转写前后的判断准确率
2. 分析不同模型在相同数据上的表现
3. 识别仍需改进的判断类型
