# 海龟汤与规则怪谈AI裁判优化项目开发日志

## 2024年12月 - 准确率量化评分系统开发记录

### 项目启动与需求确认

#### 初始问题描述
**用户原始需求：**
> "现在有个问题，我要针对用户去做最后报告输出，就是用户根据问题猜出来海龟汤后，他最后要对用户的准确率进行判断，只有80%以上才能算通过。这是现有的提示词，但是问题就在于现在的结果无法量化，比如说主干站60%，那么什么算主干呢，或者其余的非主干的修饰或者氛围词，占40%，那么这个又怎么算，这点给出几个方案吧"

**问题分析：**
1. **量化困难**：现有系统提到"主干占60%"但无法定义什么是"主干"
2. **标准缺失**：修饰性内容占40%但无法量化评估
3. **判断模糊**：80%准确率无明确的计算方法
4. **工具错位**：发现现有"准确率判断提示词"实际是多问题判断工具

#### 需求确认过程
**开发者理解并复述需求：**
> "你需要优化海龟汤内容解析专家提示词，采用方案二（必要信息点检查法）作为准确率评判标准。具体要求：双输出架构（第一个代码块是原有详细解析，第二个代码块是专门的必要信息点评分内容），为后续80%准确率判断提供标准化评分点。"

**用户确认：**"正确，开始执行"

### 解决方案设计阶段

#### 设计思路与决策过程
**开发者响应：**"我提供几个量化解决方案"

**用户要求细化：**"分别使用例子举例解释这几个方案的应用案例，就拿给你的这个海龟汤..."（提供了具体的"蓝色栅栏"案例作为测试用例）

#### 四种方案设计与案例验证
**测试用例：**
- **汤面：**"我仍然经常不受控制地想起那个诡异的秋日清晨...看到了一排蓝色栅栏..."
- **汤底：**叙述者是脑部受损的受害者，"蓝色栅栏"是白化症凶手精神病服的条纹，最终被凶手杀死

设计了四种不同的量化评分方案：

**方案一：分级权重评分系统**
- 核心真相（40%）+ 关键事件（30%）+ 重要细节（20%）+ 背景氛围（10%）
- 优势：简单直观，突出重点
- 缺陷：权重设定主观性较强

**方案二：必要信息点检查法**  
- 10个必须项 + 3-5个加分项
- 必须项≥80%通过，或必须项≥70%+加分项≥50%补偿通过
- 优势：标准化程度最高，便于AI自动判断
- 缺陷：信息点划分需要精心设计

**方案三：层次递进评估法**
- 表面理解（20%）+ 因果理解（35%）+ 细节理解（25%）+ 深层理解（20%）
- 优势：全面评估理解深度
- 缺陷：实施复杂度高

**方案四：错误扣分制**
- 从100分开始，根据错误类型扣分
- 核心错误-30分，重要错误-15分，一般错误-8分，轻微错误-3分
- 优势：直观明确，便于反馈
- 缺陷：扣分标准设计复杂

#### 方案对比与选择

通过具体案例（"蓝色栅栏"海龟汤）对四种方案进行详细演示：

**测试案例概要：**
- 汤面：主角回忆诡异清晨，看到蓝色栅栏，现住在其中
- 汤底：主角是脑部受损的受害者，"蓝色栅栏"是白化症凶手的精神病服条纹，最终被凶手杀死

**方案测试结果：**
- 方案一：用户A得分82%（通过）
- 方案二：用户B必须项80%（通过），用户C补偿通过
- 方案三：用户C得分77.5分（不通过）  
- 方案四：用户D得分21分（严重不通过）

**决策过程记录：**
开发者分析："推荐使用**方案二（必要信息点检查法）**，原因如下：
1. **标准化程度最高** - 便于制定统一评判标准
2. **便于AI实施** - 逻辑清晰，容易程序化  
3. **评分透明** - 用户可以清楚知道哪些要点掌握了
4. **灵活性好** - 可以根据不同难度调整必须项数量"

**用户确认选择：**"那现在就选择方案二，然后优化一下提示词吧"

#### 第六步：评判标准优化（宽松化调整）

**用户需求：**"匹配再调松一点，有提到相关的内容、意思相近、方向正确就能算分"

**技术实现：**
1. **匹配原则调整**
   - 原标准：严格按照标准得分点进行判断，用户回答中明确体现的信息才能算作答对
   - 新标准：宽松匹配原则，有提到相关内容、意思相近、方向正确就能算分

2. **具体优化内容**
   - 必须项描述优化：从"是否理解"改为"提及或暗示相关内容"
   - 加分项描述优化：从严格匹配改为"涉及相关内容"
   - 评判指导更新：避免过度严格的字面匹配，重点评判核心概念掌握

3. **修改细节**
   - 核心身份认知：用户回答中提及或暗示主要角色身份相关内容
   - 关键事件理解：用户回答涉及核心事件或相关描述
   - 隐喻解析：用户表现出对关键隐喻的理解或接近理解
   - 其他项目类似调整，增加"相关"、"涉及"、"接近"等宽松匹配词汇

**优化效果：**
- 降低误判风险：避免因表达方式不同导致的得分损失
- 提高用户体验：更符合实际理解情况的评分标准
- 保持评估质量：在宽松的同时仍然保持有效的区分度

#### 第七步：评分逻辑优化（更合理的分数分配）

**用户要求：**调整评分规则，让分数分配更合理

**具体修改：**
- 答对0个：0分
- 答对1个：20分  
- 答对2-3个：40分
- 答对4-5个：60分
- 答对6个以上：每个10分

**补偿机制：**
- 如果答对6-7个必须项，每个加分项可以额外加5分
- 比如：7个必须项(70分) + 2个加分项(10分) = 80分，就能通过

**最终标准：**
- 总分达到80分就通过，不够就不通过

#### 第八步：判断稳定性优化（解决评分波动问题）

**问题发现：**
用户反馈同一输入出现评分不稳定，有时75分有时90分，判断结果波动较大。

**问题分析：**
- 原因1：匹配标准过于模糊（"提及或暗示"、"接近理解"等主观表述）
- 原因2：缺乏具体的匹配判断指导，AI每次理解不一致
- 原因3：没有明确的匹配示例和边界案例说明

**第一轮优化：增加具体匹配标准**
```
匹配判断的具体标准：
- 用户提到了信息点中的核心概念或关键词 → ✓
- 用户的表述在逻辑上与信息点一致，即使用词不同 → ✓  
- 用户理解了事件的本质，哪怕细节表达有差异 → ✓
```

**效果反馈：**
- ✅ 判断稳定性大幅提高
- ❌ 但出现给分过高问题（90分 vs 期望75-80分）

#### 第九步：评分严格度调整（防止给分过高）

**问题分析：**
用户回答遗漏了关键信息（如"院长之子"、"白化症"、"认知受损程度"、"病床上被杀"等），但仍获得90分，明显过高。

**调整策略：**
1. **提高匹配门槛**
   - "提到"改为"明确提到"
   - 增加"且包含主要信息要素"要求
   - 明确"泛泛提及，缺少关键细节"不合格

2. **严格化评分原则**
   - 强调"准确理解"而非"大概理解"
   - "关键信息不能遗漏"
   - "泛泛的、模糊的表述不算理解"
   - "宁可严格一些，确保真正理解才给分"

**预期效果：**
- 同样的用户回答从90分降至75-80分
- 保持判断稳定性的同时，确保评分准确性

#### 第十四步：通用XML标签去除工具创建（文本处理优化）

**用户需求：**
"帮我写一个正则<提示>派对的举办状态可能与预期不同</提示> 想办法吧xml和里面的内容去除"

**问题分析：**
- 需要去除文本中的XML标签及其包含的内容
- 要求通用性，适用于任意标签名称
- 参考之前的JSON字段提取经验

**技术实现：**

1. **通用正则表达式设计**
   ```javascript
   {{内容}}.replace(/<[^>]*>[\s\S]*?<\/[^>]*>/g, '')
   ```

2. **创建专用文档**
   - 文件：`/去除XML标签正则表达式.md`
   - 包含详细的使用说明和多种场景示例
   - 支持多行内容和嵌套结构处理

**正则表达式解析：**
- `<[^>]*>` - 匹配任意开始标签
- `[\s\S]*?` - 非贪婪匹配任意字符（包括换行）
- `<\/[^>]*>` - 匹配任意结束标签
- `g` - 全局匹配标记

**通用性验证：**
- ✅ 处理 `<提示>内容</提示>`
- ✅ 处理 `<system-reminder>内容</system-reminder>`
- ✅ 处理任意标签名称和多行内容
- ✅ 支持多个标签同时处理

**应用价值：**
- 为文本预处理提供标准化工具
- 可用于清理AI输出中的标记内容
- 通用性强，适用于各种XML/HTML标签清理需求
