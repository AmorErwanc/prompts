# 私密角色创建提示词 v5 测试集

## 测试目标
验证AI能否:
1. 从完整输入中一次性提取所有角色信息
2. 在多轮对话中逐步收集并整理角色信息
3. 智能优化和丰富用户提供的基础描述
4. 正确处理各个阶段的状态转换

---

## 测试用例 1: 完整信息单次输入测试

### 测试目的
验证AI能否从一段完整描述中准确提取全部8个字段信息

### 用户输入
```
我的私密角色是我读高中时候的高中女同学,性格比较温柔、傲娇,语言风格刀子嘴豆腐心,和我是青梅竹马,过往经历是从小与我一起长大,住在隔壁,父母是世交。她成绩优异,尤其擅长绘画,却从不轻易展示作品。表面上常对我毒舌,实则默默关注我的一举一动,会偷偷帮我整理笔记,在我生病时第一时间送来药品却嘴硬说是顺手。她叫苏婉清。
```

### 预期提取结果
- **name**: 苏婉清
- **gender**: 女
- **identity**: 高中同学
- **personality_traits**: ["温柔", "傲娇", "关心他人", "口是心非", "成绩优异", "擅长绘画", "低调内敛"]
- **speaking_style**: 刀子嘴豆腐心,表面毒舌实则关心
- **background_story**: 从小与用户一起长大,住在隔壁,父母是世交。成绩优异,尤其擅长绘画但不轻易展示作品
- **relationship_with_user**: 青梅竹马
- **additional_info**: 会偷偷帮用户整理笔记,在用户生病时第一时间送来药品却嘴硬说是顺手

### 预期AI行为
- 状态应为 `collecting`
- 应识别出所有已提供的信息
- 可能追问1-2个优化性问题(如具体年龄、更详细的说话习惯等)

## 测试用例 3: 多轮对话渐进式输入测试

### 测试目的
验证AI在多轮对话中能否准确累积和整合信息

### 第一轮用户输入
```
我想创建一个女生角色,她是我的大学学姐
```

**预期AI行为:**
- 提取: name(null), gender(女), identity(大学学姐)
- 追问性格、说话风格、关系等信息

---

### 第二轮用户输入
```
她叫陈雨欣,性格独立自信,有点高冷,但对我还挺照顾的
```

**预期AI行为:**
- 累积信息: name(陈雨欣), gender(女), identity(大学学姐), personality_traits(["独立", "自信", "高冷", "照顾他人"])
- 推断: relationship_with_user可能是"学姐学弟关系,彼此关照"
- 继续追问说话风格、背景故事等

---

### 第三轮用户输入
```
她说话简洁利落,不喜欢拖泥带水。她是学生会副会长,成绩全系第一,很多人追她但她都拒绝了
```

**预期AI行为:**
- 补充信息: speaking_style(简洁利落,直截了当), background_story(学生会副会长,成绩全系第一,追求者众多但都拒绝)
- 可能追问用户与她的具体相处细节、特殊经历等

---

### 第四轮用户输入
```
我们是通过社团活动认识的,她是社长我是新人。刚开始她对我挺严格,后来发现我很努力就开始主动帮我,还会请我吃饭
```

**预期AI行为:**
- 补充 relationship_with_user: 社团学姐学弟关系,从严格到关照的转变
- 补充 additional_info: 通过社团认识,学姐会主动帮助和请吃饭
- 如果所有关键字段已填充,进入 `confirming` 状态

## 测试用例 4: 混乱逻辑整理测试

### 测试目的
验证AI能否整理用户混乱的表达,提取有效信息并优化

- **personality_traits**: ["霸道", "强势", "可靠", "宠溺", "外表冷酷", "内心温柔", "细心", "记忆力好"]

- **additional_info**: 会记得用户说过的每一件小事

### 预期AI行为
- 能从混乱表达中提取完整信息
- 将"有点像霸道总裁"优化为具体的性格特征
- 整理出清晰的角色框架

## 测试用例 6: confirming 阶段测试

### 测试目的
验证AI能否正确触发确认阶段并处理用户反馈

### 前置条件
假设已通过多轮对话收集到完整信息:
```json
{
  "name": "江澄",
  "gender": "男",
  "identity": "古风世界的世家少主",
  "personality_traits": ["傲娇", "刀子嘴豆腐心", "正直", "护短"],
  "speaking_style": "说话直接,经常嘴硬,偶尔冒出一两句狠话但行动上很温柔",
  "background_story": "云梦江氏少主,自幼习武,性格被家族期待塑造得强势,实则内心柔软",
  "relationship_with_user": "青梅竹马",
  "additional_info": "会在用户遇到危险时第一时间出现,嘴上说着嫌弃实则默默准备用户喜欢的点心"
}
```

### 场景 A: 用户确认
**用户输入:** `确认` 或 `好的` 或 `没问题`

**预期AI行为:**
- 状态变更为 `confirmed`
- 返回最终角色档案
- 给出鼓励性的结束语

---

### 场景 B: 用户修改
**用户输入:** `等等,我想改一下他的性格,再加上一个特点:他虽然傲娇但其实很会撒娇`

**预期AI行为:**
- 状态保持为 `collecting`
- 更新 personality_traits 数组,添加"会撒娇"
- 可能补充相关的 speaking_style 或 additional_info
- 再次询问是否确认

## 测试评估标准

### 1. 信息提取准确性
- ✅ 所有明确提及的信息都被正确提取
- ✅ 没有遗漏用户提供的任何细节
- ✅ 信息归类正确(如将"医生"归为identity而非personality)

### 2. 智能优化能力
- ✅ 能从简单描述推断相关信息(如从"医生"推断"有责任心")
- ✅ 能整理混乱表达,形成清晰结构
- ✅ 主动补充合理的角色细节

### 3. 对话流畅性
- ✅ 回复语调自然亲切,不超过150字
- ✅ 追问时机合理,不过度询问
- ✅ 每次只追问1-3个问题,不让用户感到负担

### 4. 状态管理准确性
- ✅ collecting → confirming → confirmed 流程正确
- ✅ 修改信息时能正确返回 collecting 状态
- ✅ 所有字段填充完毕才进入 confirming 状态

### 5. JSON格式规范性
- ✅ 输出严格符合JSON格式
- ✅ 包含 reply, status, character_profile 三个字段
- ✅ character_profile 包含全部8个字段,缺失信息标记为null

---

## 使用建议

1. **按顺序测试**: 先测试完整输入(用例1),再测试多轮对话(用例3),最后测试边界情况
2. **记录AI表现**: 对比预期结果与实际输出,记录偏差点
3. **迭代优化**: 根据测试结果调整提示词,重点关注信息遗漏和逻辑整理能力
4. **真人测试**: 邀请真实用户进行盲测,收集自然对话数据
